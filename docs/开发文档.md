# mdairy 开发文档

> Markdown 笔记软件 · 查看和编辑本地 md 文件夹 · 桌面应用
> 本文档记录立项分析（参考开源项目 SoloMD）与已确认的开发共识，作为实施的唯一依据。
> 状态：需求已确认，未开工。UI 设计与交互见 [页面需求文档](./页面需求文档.md)。

## 1. 产品定义

- **一句话**：macOS 优先的桌面 Markdown 笔记软件，打开一个本地文件夹（vault），查看和编辑其中的 `.md` 文件。
- **定位**：自用工具/学习项目为主，代码结构上保留以后公开发布的可能（模块化、配置与数据分离）。
- **原则**：纯本地、无服务器、文件即数据库（不引入私有格式，不锁定用户数据）。

## 2. 参考项目分析：SoloMD

仓库：<https://github.com/zhitongblog/solomd>（MIT，2026-04 创建，1100+ star，v4.14.6）
结论先行：**不 fork，从零自建，参考其选型与模块划分；遇难点（文件监听冲突、编码检测、滚动同步）读它对应单文件的实现。**

### 2.1 概况

- Tauri 2 + Vue 3 + CodeMirror 6 + markdown-it。
- 前端约 11.4 万行（307 个 Vue/TS 文件），Rust 后端约 3 万行（46 个模块）。
- 代码几乎全部由 Claude Code 生成，一人维护。
- 核心卖点不只是 md 编辑，而是把 AI Agent 深度嵌入编辑器（Agent 面板、YAML Recipe 定时任务、MCP server 等）——这些不在本项目范围内。

### 2.2 功能点（它的全集，本项目只取子集）

| 类别 | 功能 |
|---|---|
| 编辑核心 | WYSIWYG 实时编辑（Typora 风格）、源码模式、Vim 模式、标签页 + 分屏、大纲、KaTeX、Mermaid、图片粘贴到 `_assets/`、front-matter、CJK 编码识别 |
| 文件管理 | 多 vault、文件树、快速切换器、命令面板、全文搜索、语义搜索（RAG）、wikilink + 反链、标签、文件监听 |
| 版本同步 | AutoGit（内嵌 libgit2 本地提交）、GitHub/GitLab/Gitea 同步 + E2EE、云盘目录识别 |
| AI/Agent | BYOK 14 家、Agent 面板、Recipe 定时任务、git 分支沙箱 + Accept、可重放 trace、Ollama、成本统计 |
| 集成 | 内置 MCP server、本地 REST API、web-clipper、iOS 快捷指令、快速捕捉 |
| 导出 | Pandoc、docx、PDF、reveal.js 演讲模式 |
| 其他 | 番茄钟、tldraw 白板、14 语言 i18n、iOS/Android |

### 2.3 值得借鉴的选型与优点

- **技术选型是当前自建 md 编辑器的最优组合**：Tauri 2（包小内存低）+ CodeMirror 6（markdown 编辑事实标准）+ markdown-it（渲染管线插件化），MIT 协议可自由借鉴。
- **分层清晰**：Rust 侧一个功能一个模块（`git_history.rs`、`search.rs`…），前端 store 按领域拆分，边界清楚。
- **本地优先、安全习惯**：纯文件夹存储、渲染过 DOMPurify、路径穿越防护、外部修改冲突处理完整——这些从零做容易漏，实现可参考。

### 2.4 缺点 / 引以为戒

- 体量 14.5 万行，对本项目需求约 95% 是多余的；fork 的理解成本高于自建。
- 巨型组件：`Editor.vue` 5135 行、`FileTree.vue` 3210 行——本项目拆小时刻意避免。
- WYSIWYG 是全项目最难的部分，本期明确不做。
- AI 生成代码质量参差、前端混入 React（tldraw 所致）两套 UI 框架并存——混框架问题本项目不存在。

### 2.5 模块划分参考（映射到本项目）

1. 文件系统层（Rust）：工作区、CRUD、编码检测、文件监听
2. 编辑器层：CodeMirror 6 封装、markdown 语法
3. 渲染层：markdown-it 管线 + 插件 + 消毒
4. UI 壳：布局、文件树、大纲、命令面板、设置
5. 索引与搜索
6. 版本/同步（后置）
7. AI/集成（后置）

## 3. 已确认的决策（Grilling 共识）

| 决策点 | 结论 |
|---|---|
| 产品形态 | 桌面应用，Tauri 2，macOS 优先（保留扩展 Win/Linux 的可能） |
| 起步策略 | 从零自建，参考 SoloMD 选型与模块划分 |
| 定位 | 自用为主，结构上保留发布可能 |
| MVP 范围 | 必做项全部 + 原定"可做可不做"项全部（见 §4） |

| 图片粘贴 | 存 `vault/_assets/`，插入相对路径 |
| UI 语言 | 中文硬编码 |
| 预览形态 | 三态切换：纯编辑 / 分栏（默认）/ 纯预览，滚动同步 |

| # | 功能 | 说明 |

| 7 | 全文搜索 | vault 内全文搜索面板，结果点击定位打开 |
| 8 | 大纲 | 从当前文件标题生成，点击滚动跳转 |

## 5. 技术栈

- **壳**：Tauri 2（Rust）；`tauri-plugin-dialog`、`tauri-plugin-fs`；`notify` 文件监听；`encoding_rs` 编码检测
- **前端**：React + TypeScript + Vite；Zustand 状态管理
- **编辑器**：CodeMirror 6（`@codemirror/lang-markdown`）
- **渲染**：markdown-it + KaTeX + Mermaid（懒加载）+ highlight.js + DOMPurify

## 6. 模块划分

```
src-tauri/src/
  workspace.rs   打开/记忆 vault、路径安全
  files.rs       读/写/建/删/改名、编码检测
  watcher.rs     文件变更事件推送前端
src/
  lib/markdown.ts    渲染管线（插件注册、消毒、Mermaid 懒加载）
  stores/
    workspace.ts     文件树、当前工作区、当前文件
    tabs.ts          标签页、脏状态、保存
    settings.ts      主题、视图模式
  components/
    AppShell         整体布局（侧栏 / 主区 / 状态）
    FileTree         文件树 + CRUD
    TabBar           标签页
    EditorPane       CodeMirror 6 封装
    PreviewPane      渲染预览 + 滚动同步
    OutlinePanel     大纲
    SearchPanel      全文搜索
    CommandPalette   命令面板
    ConflictDialog   外部修改冲突弹窗
```

约定：

- 单组件不超过约 400 行，超了就拆（对比 SoloMD 的巨型组件教训）。
- 所有接受路径的 Tauri command 做路径穿越校验（拒绝 `..` 与绝对路径逃逸）。
- 渲染输出一律过 DOMPurify 再入 DOM。
